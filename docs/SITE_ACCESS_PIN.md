# نظام الرقم السري للدخول (Site Access PIN)

## نظرة عامة

الموقع مجهز بنظام حماية متقدم يتطلب رقم سري (PIN) للدخول إلى المنصة. هذا النظام يحمي الموقع بالكامل من الدخول غير المصرح به.

## الميزات الأمنية

### 1. الرقم السري الافتراضي
- الرقم السري الحالي: **2025**
- يمكن تغييره من ملف `.env` في مجلد `frontend`

### 2. آلية الحماية
- **محاولات محدودة**: 5 محاولات فقط قبل القفل المؤقت
- **قفل مؤقت**: 10 دقائق بعد استنفاذ المحاولات
- **تخزين دائم**: يتذكر النظام المستخدمين المصرح لهم
- **تشفير الجلسة**: يستخدم sessionStorage لتتبع المحاولات الفاشلة

### 3. تجربة المستخدم
- واجهة عربية كاملة RTL
- تصميم كمي حديث مع جسيمات متحركة
- حقول PIN واضحة وسهلة الاستخدام
- دعم اللصق (Paste) للإدخال السريع
- تنقل بلوحة المفاتيح (أسهم + Backspace)

## كيفية تفعيل/تعطيل الحماية

### تفعيل الحماية (الحالة الحالية)

1. افتح ملف `frontend/.env`
2. اضبط المتغير:
   ```env
   VITE_SITE_ACCESS_CODE=2025
   ```

### تغيير الرقم السري

1. افتح ملف `frontend/.env`
2. غيّر القيمة إلى الرقم المطلوب:
   ```env
   VITE_SITE_ACCESS_CODE=رقمك-السري-هنا
   ```
3. أعد بناء المشروع:
   ```bash
   cd frontend
   npm run build
   ```

### تعطيل الحماية (فتح الموقع للجميع)

1. افتح ملف `frontend/.env`
2. احذف القيمة أو اتركها فارغة:
   ```env
   VITE_SITE_ACCESS_CODE=
   ```
3. أعد بناء المشروع:
   ```bash
   cd frontend
   npm run build
   ```

**ملاحظة**: إذا كان `VITE_SITE_ACCESS_CODE` فارغاً، سيستخدم النظام الرقم الافتراضي `2025` المعرّف في الكود.

## كيفية إلغاء الحماية نهائياً

إذا أردت إلغاء الحماية نهائياً من الكود:

1. افتح `frontend/src/App.tsx`
2. احذف السطر:
   ```tsx
   <SiteAccessGate>
     {children}
   </SiteAccessGate>
   ```
3. واستبدله بـ:
   ```tsx
   {children}
   ```

## البنية التقنية

### الملفات ذات الصلة

```
frontend/
├── src/
│   ├── App.tsx                      # نقطة التكامل الرئيسية
│   └── components/
│       └── SiteAccessGate.tsx       # مكون الحماية الرئيسي
└── .env                             # إعدادات الرقم السري
```

### آلية العمل

1. **App.tsx** يلف كل المحتوى بـ `<SiteAccessGate>`
2. **SiteAccessGate** يفحص localStorage للتحقق من الجلسات السابقة
3. إذا لم يكن المستخدم مصرحاً، يعرض شاشة إدخال PIN
4. بعد الإدخال الصحيح، يحفظ الحالة في localStorage
5. يحمي من الهجمات بنظام القفل المؤقت في sessionStorage

### متغيرات البيئة

| المتغير | القيمة الافتراضية | الوصف |
|---------|-------------------|-------|
| `VITE_SITE_ACCESS_CODE` | `2025` | الرقم السري للدخول |
| `DEFAULT_PIN` | `2025` | الرقم الاحتياطي في الكود |

### الثوابت الأمنية

```typescript
const MAX_ATTEMPTS = 5;                    // عدد المحاولات المسموحة
const LOCKOUT_MS = 10 * 60 * 1000;        // مدة القفل: 10 دقائق
const STORAGE_KEY = 'qurabia.siteAccess';  // مفتاح التخزين
```

## الحالة الحالية

✅ **النظام مفعّل حالياً**
- الرقم السري: `2025`
- الحماية نشطة على جميع صفحات الموقع
- لن يتمكن أحد من الدخول بدون الرقم السري

## الأسئلة الشائعة

### س: كيف أعرف أن الحماية مفعّلة؟
ج: عند زيارة الموقع، ستظهر لك شاشة إدخال PIN قبل الوصول إلى المحتوى.

### س: ماذا لو نسيت الرقم السري؟
ج: يمكنك الوصول إلى الرقم من ملف `frontend/.env` أو من الكود في `SiteAccessGate.tsx` (السطر 5).

### س: هل يمكن استخدام أحرف بدلاً من أرقام؟
ج: نعم، يمكنك استخدام أي نص في `VITE_SITE_ACCESS_CODE`، لكن واجهة المستخدم حالياً مصممة للأرقام فقط.

### س: كيف أزيل الحماية مؤقتاً للاختبار؟
ج: افتح console المتصفح واكتب:
```javascript
localStorage.setItem('qurabia.siteAccess', '2025')
```
ثم أعد تحميل الصفحة.

### س: هل الحماية تعمل في وضع التطوير؟
ج: نعم، تعمل في جميع الأوضاع (development, production).

## الأمان

⚠️ **تحذيرات أمنية مهمة**:

1. **لا تضع الرقم السري في Git**: ملف `.env` مُضاف إلى `.gitignore`
2. **غيّر الرقم الافتراضي**: `2025` هو رقم تجريبي، استخدم رقم فريد
3. **استخدم HTTPS**: تأكد من أن الموقع يعمل على HTTPS في الإنتاج
4. **راقب المحاولات الفاشلة**: يمكن إضافة logging للمحاولات الفاشلة
