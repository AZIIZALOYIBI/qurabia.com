# بوابة الوصول للموقع — Site Access Gate

## نظرة عامة

تم تفعيل نظام حماية شامل للموقع باستخدام رمز PIN. يتطلب هذا النظام من جميع الزوار إدخال رمز الوصول قبل عرض أي محتوى.

## كيف يعمل النظام

### 1. **في صفحة الهبوط** (`landing.html`)
- عند زيارة `landing.html`، يتحقق JavaScript من وجود `localStorage['qurabia.siteAccess']`
- إذا لم يكن موجوداً → يحوّل الزائر إلى `/?app=1&_from=landing`
- هذا يعرض مكون `SiteAccessGate` في تطبيق React

### 2. **في تطبيق React** (`App.tsx`)
- مكون `SiteAccessGate` يغلف التطبيق بالكامل
- يطلب من المستخدم إدخال رمز PIN
- بعد المصادقة الناجحة:
  - يحفظ الحالة في `localStorage['qurabia.siteAccess']`
  - إذا جاء من `landing.html` → يعيد التوجيه إليها
  - وإلا → يعرض التطبيق مباشرة

### 3. **الحماية من المحاولات المتكررة**
- الحد الأقصى: 5 محاولات خاطئة
- عند تجاوز الحد → قفل لمدة 10 دقائق
- حالة القفل محفوظة في `sessionStorage['qurabia.gateLock']`

## ضبط رمز الوصول

### التطوير المحلي

قم بإنشاء ملف `.env` في مجلد `frontend/`:

```bash
VITE_SITE_ACCESS_CODE=رمز-سري-هنا
```

أو اتركه فارغاً لاستخدام الرمز الافتراضي `2025`.

### الإنتاج (GitHub Pages)

1. اذهب إلى إعدادات المستودع على GitHub:
   ```
   Settings → Secrets and variables → Actions
   ```

2. أضف Secret جديد:
   - **الاسم**: `VITE_SITE_ACCESS_CODE`
   - **القيمة**: الرمز السري الذي تريده (مثل: `7891` أو `mysecret2025`)

3. GitHub Actions سيستخدم هذا السر تلقائياً عند البناء والنشر

### ملاحظات مهمة

- **لا تشارك الرمز علناً** — استخدم GitHub Secrets دائماً
- الرمز يُدمج في البناء النهائي، لكنه مخفي في المتغيرات البيئية
- إذا تركت `VITE_SITE_ACCESS_CODE` فارغاً → سيستخدم النظام الرمز الافتراضي `2025`

## إزالة القفل

إذا أردت تعطيل القفل تماماً:

1. **في GitHub Secrets**: احذف أو فرّغ `VITE_SITE_ACCESS_CODE`
2. **في الكود**: علّق السطر 449 في `App.tsx`:
   ```tsx
   // <SiteAccessGate>
   //   ...
   // </SiteAccessGate>
   ```
3. **في landing.html**: احذف أو علّق السكريبت (السطور 1502-1512)

## الأمان

- ✅ حماية من هجمات القوة الغاشمة (brute force) عبر نظام القفل
- ✅ الرمز محفوظ في localStorage (دائم) وsessionStorage (مؤقت للقفل)
- ✅ التحقق يحدث في الواجهة الأمامية (client-side)
- ⚠️ **تنبيه**: هذه حماية على مستوى الواجهة الأمامية فقط، وليست بديلاً عن المصادقة الخلفية
