# دليل الرسوم التقنية لبراءات الاختراع
## Patent Technical Drawings Guide

---

## 1. المعايير الدولية للرسوم

### 1.1 متطلبات PCT/WIPO (القاعدة 11 من اللوائح)

```
الأبعاد:
  ورق: A4 (21 × 29.7 سم) أو Letter (21.6 × 27.9 سم)
  هوامش دنيا:
    أعلى:    2.5 سم
    أيسر:    2.5 سم
    أيمن:    1.5 سم
    أسفل:    1.0 سم
  منطقة الرسم القصوى: 26.2 × 17.0 سم

الخطوط:
  الجودة: سوداء واضحة على خلفية بيضاء
  سُمك الخطوط الرئيسية: 0.4 - 0.6 ملم
  سُمك الخطوط الثانوية: 0.2 - 0.3 ملم
  لا ألوان، لا ظلال تدرجية (gradient)
  التظليل بالهاشور المتوازي مقبول

النصوص:
  حد أدنى لحجم النص: 3.2 ملم (قياس الحرف الكبير)
  لغة الأرقام المرجعية: أرقام عربية (1، 2، 3...) أو هندية-عربية
  لا نصوص وصفية داخل الرسم (إلا المحاور والوحدات)
```

### 1.2 متطلبات SAIP الإضافية

```
- الأرقام المرجعية بالعربية مُفضَّلة للإيداع السعودي
- عنوان الشكل: "الشكل [رقم]" أسفل كل رسم
- ترقيم الصفحات: "ص [N] من [M]" في حال وجود صفحات متعددة
- رمز الاختراع (يُضيفه المكتب بعد الإيداع — لا تضعه أنت)
```

## 2. الأنواع الأساسية للرسوم التقنية

### 2.1 المخطط الكتلي (Block Diagram)

**الاستخدام**: الأنظمة والشبكات والمعالجة الرقمية

```
معايير المخطط الكتلي:
  - المستطيلات للمكونات الرئيسية
  - الخطوط المستقيمة للاتصالات
  - رؤوس الأسهم لتحديد اتجاه التدفق
  - لا تقاطعات بصرية إن أمكن
  - المجموعات المترابطة داخل خط منقط

مثال بنية SVG:
<svg viewBox="0 0 800 500" xmlns="http://www.w3.org/2000/svg">
  <!-- وحدات كمستطيلات -->
  <rect x="50" y="200" width="120" height="60" 
        fill="white" stroke="black" stroke-width="2"/>
  <text x="110" y="235" text-anchor="middle" font-size="14">الوحدة (10)</text>
  
  <!-- خط اتصال مع سهم -->
  <line x1="170" y1="230" x2="250" y2="230" 
        stroke="black" stroke-width="2"
        marker-end="url(#arrow)"/>
  
  <!-- تعريف رأس السهم -->
  <defs>
    <marker id="arrow" markerWidth="10" markerHeight="7" 
            refX="10" refY="3.5" orient="auto">
      <polygon points="0 0, 10 3.5, 0 7" fill="black"/>
    </marker>
  </defs>
</svg>
```

### 2.2 مخطط التدفق (Flowchart)

**الاستخدام**: طرق وعمليات وخوارزميات

```
الأشكال القياسية:
  ◯ بيضاوي/مستدير: بداية / نهاية
  □ مستطيل:        عملية / خطوة
  ◇ معين:          قرار (نعم/لا)
  ▱ متوازي الأضلاع: إدخال / إخراج
  ⬡ سداسي:         مرحلة معالجة معقدة

ترتيب التدفق:
  - من الأعلى للأسفل (الافتراضي)
  - حلقات التكرار تعود يساراً عادةً
  - كل قرار له فرعان واضحان: نعم / لا
```

### 2.3 الرسم التفجيري (Exploded View)

**الاستخدام**: الأجهزة الميكانيكية والمنتجات المادية

```
مبادئ الرسم التفجيري:
  - الأجزاء مُبعدة على خطوط محاذاة (explosion lines)
  - الخطوط المنقطة تربط الجزء بموضعه التجميعي
  - ترقيم تسلسلي واضح لكل جزء
  - إسقاط إيزومتري (30° من الأفق) للأجهزة ثلاثية الأبعاد
  - إسقاط أمامي + جانبي + علوي للأجسام المعقدة
```

### 2.4 المخطط التسلسلي (Sequence Diagram)

**الاستخدام**: بروتوكولات الاتصال وتفاعلات الأنظمة

```
القواعد:
  - كل كيان (Entity) عمود عمودي
  - الرسائل خطوط أفقية بالتسلسل الزمني
  - الوقت يتدفق من الأعلى للأسفل
  - الرسائل المتزامنة تُشار بخط أفقي مزدوج
```

### 2.5 الرسم التفصيلي بالأرقام المرجعية

```
الترقيم المرجعي المُوصى:
  العناصر الرئيسية: أعداد زوجية 10, 20, 30, 40...
  الأجزاء الفرعية: 11, 12, 13... (فروع العنصر 10)
  المجموعات: 100, 200, 300... للأجزاء الكبرى

خطوط الإشارة (Leader Lines):
  - خط مستقيم أو بزاوية واحدة
  - تنتهي بنقطة على الجزء المُشار إليه
  - الرقم داخل دائرة صغيرة أو بجانب خط أفقي قصير
```

## 3. بناء رسوم SVG للإيداع

### 3.1 القالب الأساسي

```svg
<?xml version="1.0" encoding="UTF-8"?>
<svg viewBox="0 0 800 600" 
     xmlns="http://www.w3.org/2000/svg"
     font-family="Arial, sans-serif">
  
  <!-- عنوان الشكل -->
  <text x="400" y="580" text-anchor="middle" 
        font-size="14" font-weight="bold">الشكل 1</text>
  
  <!-- حدود منطقة الرسم -->
  <rect x="10" y="10" width="780" height="550" 
        fill="none" stroke="#cccccc" stroke-width="0.5"/>
  
  <!-- محتوى الرسم هنا -->
  
</svg>
```

### 3.2 عناصر SVG المتكررة في البراءات

```svg
<!-- مكوّن رئيسي (مستطيل بتسمية) -->
<g id="component-10">
  <rect x="100" y="100" width="150" height="80"
        fill="white" stroke="black" stroke-width="2"/>
  <text x="175" y="145" text-anchor="middle" font-size="13">
    وحدة المعالجة
  </text>
  <text x="175" y="165" text-anchor="middle" font-size="11" 
        fill="#444">(10)</text>
</g>

<!-- سهم اتجاهي -->
<defs>
  <marker id="arrowBlack" markerWidth="8" markerHeight="6"
          refX="8" refY="3" orient="auto">
    <polygon points="0 0, 8 3, 0 6" fill="black"/>
  </marker>
</defs>
<line x1="250" y1="140" x2="350" y2="140"
      stroke="black" stroke-width="2"
      marker-end="url(#arrowBlack)"/>

<!-- دائرة الرقم المرجعي -->
<circle cx="200" cy="50" r="12" fill="white" stroke="black" stroke-width="1.5"/>
<text x="200" y="55" text-anchor="middle" font-size="11">10</text>

<!-- خط مرجعي (leader line) -->
<line x1="212" y1="50" x2="250" y2="80" stroke="black" stroke-width="1"/>
<line x1="250" y1="80" x2="300" y2="80" stroke="black" stroke-width="1"/>

<!-- تظليل هاشور (بديل الألوان) -->
<defs>
  <pattern id="hatch" patternUnits="userSpaceOnUse" width="6" height="6"
           patternTransform="rotate(45)">
    <line x1="0" y1="0" x2="0" y2="6" stroke="black" stroke-width="1"/>
  </pattern>
</defs>
<rect x="400" y="100" width="150" height="80" fill="url(#hatch)"/>
```

## 4. قائمة مرجع الأرقام (Reference Numeral List)

**يجب أن تُنتج دائماً قائمة مرجع كاملة:**

```markdown
## قائمة الأرقام المرجعية | Reference Numerals

| الرقم | المكوّن (عربي) | Component (English) |
|-------|---------------|---------------------|
| 10    | وحدة الاستشعار | Sensor Unit |
| 12    | مستشعر الحرارة | Temperature Sensor |
| 14    | مستشعر الضوء | Light Sensor |
| 20    | وحدة المعالجة | Processing Unit |
| 22    | المعالج الرئيسي | Main Processor |
| 30    | وحدة الإخراج | Output Unit |
| 40    | وحدة الاتصال | Communication Unit |
| 100   | الجهاز الكامل | Complete Device |
```

## 5. التحقق من جودة الرسوم

```
قبل تضمين أي رسم في البراءة، تحقق من:

الشكل:
  □ جميع الخطوط واضحة وقابلة للطباعة بالأبيض والأسود
  □ لا ألوان تحمل معنى (إذا طُبع بالأبيض والأسود ضاع المعنى)
  □ الأرقام المرجعية مقروءة ومميزة
  □ عنوان "الشكل N" موجود

المحتوى:
  □ كل شكل مذكور في وصف الرسوم في الوثيقة
  □ لا رقم مرجعي في الرسم غير موجود في الوصف
  □ لا تناقض بين الشكل والوصف النصي
  □ اتساق الأرقام المرجعية عبر جميع الأشكال (نفس الرقم = نفس المكوّن)

الكمال:
  □ كل مطالبة رئيسية مُصوَّرة بشكل واحد على الأقل
  □ Best Mode (أفضل تجسيد) مُصوَّر كاملاً
```
