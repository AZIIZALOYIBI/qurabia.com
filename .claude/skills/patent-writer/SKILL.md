# مهارة كتابة براءات الاختراع الاحترافية
## Professional Patent Drafting Skill — Filing-Ready Standard

> هذه المهارة تحوّل Claude إلى كاتب براءات اختراع محترف يُنتج وثائق جاهزة للإيداع الرسمي وفق معايير SAIP والمنظمة الدولية للملكية الفكرية (WIPO) واتفاقية PCT.

## 1. تحديد المهمة وجمع المعلومات | Task Identification & Intake

**قبل أي كتابة، اجمع المعلومات التالية من المخترع:**

```
المرحلة أ — الهوية والنطاق:
  □ اسم المخترع أو المخترعين (كامل)
  □ اسم المؤسسة/الشركة المالكة (إن وجدت)
  □ عنوان الاختراع المقترح
  □ المجال التقني (Field of Technology)
  □ الولاية القضائية المستهدفة: سعودية ☐ GCC ☐ دولية PCT ☐

المرحلة ب — الجوهر التقني:
  □ وصف الاختراع بكلمات بسيطة (ما الذي يفعله؟)
  □ المشكلة التي يحلها
  □ كيف يختلف عن الحلول الموجودة؟
  □ العناصر التقنية الأساسية (المكونات، الخطوات، التركيبات)
  □ أفضل طريقة لتنفيذ الاختراع (Best Mode)
  □ هل هناك رسومات أو مخططات أولية؟

المرحلة ج — الاستراتيجية:
  □ هل أجرى المخترع بحث فن سابق؟ (يُفضّل استخدام مهارة patent-search أولاً)
  □ هل هناك تاريخ إيداع مستهدف؟
  □ هل يُريد نموذج منفعة أم براءة اختراع كاملة؟
```

**إذا كانت المعلومات ناقصة:** اطرح الأسئلة بالترتيب أعلاه. لا تبدأ الصياغة قبل فهم المرحلتين أ وب على الأقل.

## 2. نوع الوثيقة المطلوبة | Document Type Selection

| الكود | نوع الوثيقة | متى تستخدمه |
|-------|------------|-------------|
| `FPA` | طلب براءة اختراع كامل | الإيداع الرسمي الكامل |
| `PPA` | طلب مبدئي (Provisional) | حجز تاريخ أولوية قبل الإيداع الكامل |
| `UM`  | نموذج منفعة (Utility Model) | اختراعات أبسط، حماية أسرع وأرخص |
| `ID`  | تصميم صناعي (Industrial Design) | حماية الشكل والمظهر |
| `CL`  | مطالبات فقط (Claims Only) | مراجعة أو تحسين مطالبات موجودة |
| `DS`  | وصف تقني فقط | إضافة أو مراجعة الوصف |
| `AB`  | ملخص فقط | صياغة أو مراجعة الملخص |
| `DW`  | رسوم ومخططات فقط | إعداد الرسوم التقنية |

## 3. هيكل وثيقة البراءة الكاملة | Complete Patent Document Structure

### 3.1 ترتيب مكونات الوثيقة (وفق معايير SAIP/WIPO/PCT)

```
[1] صفحة البيانات الببليوغرافية (Bibliographic Data Page)
[2] عنوان الاختراع (Title of Invention)
[3] التصريح بالأولوية (Priority Declaration) — إن وجد
[4] المجال التقني (Technical Field)
[5] الخلفية التقنية / الفن السابق (Background / Prior Art)
[6] ملخص الاختراع (Summary of the Invention)
[7] وصف الرسوم (Brief Description of Drawings) — إذا وُجدت
[8] الوصف التفصيلي (Detailed Description of Embodiments)
[9] أمثلة التطبيق (Examples) — إذا انطبق
[10] المطالبات (Claims) — القلب القانوني للبراءة
[11] الملخص (Abstract)
[12] الرسوم التقنية (Technical Drawings) — ملحق منفصل
```

**قاعدة ذهبية**: الوصف يُفسّر المطالبات، لكن المطالبات هي حدود الحماية الفعلية.

## 4. صياغة المطالبات — الفن الأصعب | Claims Drafting — The Core Art

اقرأ: `references/claims-drafting.md` للقواعد التفصيلية.

### 4.1 مبادئ المطالبات الأساسية

```
المطالبة 1 (Independent Claim):
  • أوسع نطاق ممكن مع الحفاظ على الجدة
  • كل عنصر ضروري — لا تضف قيوداً غير لازمة
  • لغة رسمية دقيقة: "يتضمن" لا "يتكوّن حصراً من"
  • جملة واحدة (مهما طالت) — هذا قانون، ليس أسلوباً

بنية المطالبة المستقلة:
  [Preamble — المقدمة]: "جهاز / طريقة / نظام لـ..."
  [Transition]: "يتضمن / يشتمل على / مؤلف من"
  [Body — الجسم]: العناصر مرقّمة ومفصولة بـ"؛"
```

### 4.2 هرمية المطالبات النموذجية (15-20 مطالبة)

```
المطالبة 1: مستقلة — جهاز (أوسع نطاق)
المطالبة 2: تابعة لـ 1 — تضيف قيداً مفضلاً
المطالبة 3: تابعة لـ 1 — تضيف بديلاً تقنياً
المطالبة 4: تابعة لـ 2 — تدخل في تفاصيل
...
المطالبة N: مستقلة — طريقة (method) لنفس الاختراع
المطالبة N+1: تابعة للطريقة
...
المطالبة الأخيرة: مستقلة — نظام (system) إذا انطبق
```

### 4.3 لغة المطالبات — مسرد رسمي

| عربي | إنجليزي مكافئ | الاستخدام |
|------|--------------|-----------|
| يتضمن / يشتمل | comprising / including | نطاق مفتوح (مُفضّل) |
| يتكوّن من | consisting of | نطاق مغلق (حصري) |
| أساساً يتكوّن | consisting essentially of | نطاق شبه مغلق |
| مقترن بـ | coupled to | اتصال وظيفي |
| متصل بـ | connected to | اتصال مادي |
| منضم إلى | attached to | ربط جسدي |
| قادر على | configured to / adapted to | وظيفة محددة |
| بحيث | wherein | إضافة قيد توضيحي |
| وفقاً للمطالبة | according to claim | في المطالبات التابعة |

## 5. الوصف التفصيلي — معايير الإفصاح الكافي | Detailed Description Standards

### 5.1 قواعد الوصف الكافي (Enablement & Written Description)

```
✓ أي شخص ذو مهارة عادية في المجال يجب أن يستطيع تنفيذ الاختراع
✓ صف أفضل طريقة معروفة للمخترع (Best Mode)
✓ صف كل التنويعات (Embodiments) المذكورة في المطالبات
✓ الرسوم يجب أن تُوصف كاملاً بالأرقام المرجعية
✓ لا تذكر في المطالبات ما لم يُوصف في الوصف
```

### 5.2 هيكل الوصف التفصيلي

```markdown
## المجال التقني
[جملتان: ما هو المجال وما هي الفئة الواسعة]

## الخلفية التقنية
[المشكلة الموجودة + حلول الفن السابق وعيوبها — دون ذكر أرقام براءات محددة بالضرورة]
[لا تقلل من الفن السابق بشكل مبالغ — قد يُستخدم ضدك]

## ملخص الاختراع
[الحل بإيجاز — يعكس المطالبة 1 بشكل رئيسي]
[مزايا الاختراع الرئيسية]

## وصف الرسوم
الشكل 1 يوضح...
الشكل 2 يُبيّن...

## الوصف التفصيلي للتجسيدات
### التجسيد الأول (Preferred Embodiment)
[وصف شامل مع أرقام مرجعية (10، 12، 14...)]

### التجسيدات البديلة
[تنويعات وبدائل — كل تنويع يُوسّع نطاق الحماية]
```

## 6. إعداد الرسوم التقنية | Technical Drawings Preparation

اقرأ: `references/drawings-guide.md` للمعايير التفصيلية.

### 6.1 أنواع الرسوم المطلوبة

| نوع الرسم | متى يُستخدم | الأداة |
|-----------|------------|--------|
| مخطط تدفق (Flowchart) | طرق وعمليات | SVG / Mermaid |
| رسم تفجيري (Exploded View) | أجهزة وأجزاء | SVG تفصيلي |
| مخطط كتلي (Block Diagram) | أنظمة وشبكات | SVG |
| مخطط دائرة (Circuit Diagram) | إلكترونيات | SVG |
| رسم مقطعي (Cross-section) | تركيبات داخلية | SVG |
| مخطط تسلسلي (Sequence Diagram) | بروتوكولات وتفاعلات | Mermaid |
| رسم هندسي (Engineering Drawing) | أبعاد وأشكال | SVG دقيق |

### 6.2 معايير الرسوم (WIPO/SAIP Standard)

```
✓ خطوط سوداء على خلفية بيضاء فقط (للإيداع الرسمي)
✓ أرقام مرجعية عربية أو إنجليزية متسقة (لا تكرار)
✓ عنوان كل شكل: "الشكل 1" أو "Fig. 1"
✓ لا نصوص داخل الرسوم (إلا للأرقام المرجعية والمحاور)
✓ جودة عالية قابلة للطباعة بـ 300 DPI على الأقل
✓ كل شكل في صفحة مستقلة إذا تجاوز الثلث الأعلى
```

### 6.3 عند إنشاء الرسوم بـ SVG

```
- استخدم viewBox="0 0 800 600" للمخططات العامة
- خطوط نظيفة: stroke-width="2" للرئيسية، "1" للتفاصيل
- أرقام مرجعية واضحة في دوائر أو بخطوط إشارة (leader lines)
- اتجاه النص: RTL للعربية، LTR للإنجليزية
- لا ألوان في الإيداع الرسمي — استخدم تظليل/هاشور للتمييز
```

## 7. متطلبات النظام السعودي | Saudi SAIP Requirements

اقرأ: `references/saudi-patent-law.md` للمتطلبات التشريعية الكاملة.

### 7.1 الجهة المختصة
**هيئة الملكية الفكرية (SAIP)** — Saudi Authority for Intellectual Property  
الموقع: www.saip.gov.sa | بوابة الإيداع: eservice.saip.gov.sa

### 7.2 أنواع الحماية في المملكة

| النوع | المدة | الرسوم التقريبية |
|-------|-------|-----------------|
| براءة اختراع | 20 سنة | SAR 900-3,600 + رسوم سنوية |
| نموذج منفعة | 10 سنوات | أقل من البراءة |
| تصميم صناعي | 5 سنوات × 3 (قابل للتجديد) | SAR 450+ |

### 7.3 المستثنيات من الحماية السعودية

```
لا تُمنح براءة في المملكة عن:
  ✗ الاكتشافات والنظريات العلمية والرياضية
  ✗ المخططات أو الأساليب الذهنية أو التجارية (بمفردها)
  ✗ برامج الحاسوب (بمفردها — لكن النظام التقني الشامل يُحمى)
  ✗ طرق التشخيص الطبي أو العلاجي (على الجسم البشري)
  ✗ أصناف النباتات والحيوانات (بالعمليات البيولوجية الأساسية)
  ✗ ما يتعارض مع أحكام الشريعة الإسلامية أو النظام العام
```

### 7.4 متطلبات اللغة

```
الإيداع السعودي: العربية إلزامية (الإيداع يُقبل بالعربية أو الإنجليزية
  مع ترجمة عربية خلال مهلة 90 يوماً للإيداع الأجنبي)
المطالبات: يجب أن تكون باللغتين في الإيداع الدولي
الرسوم: لغة محايدة (أرقام مرجعية فقط)
```

### 7.5 مسار الإيداع الوطني السعودي

```
① تقديم الطلب رقمياً عبر بوابة SAIP
② دفع رسوم الإيداع (الرسوم الأولية)
③ الفحص الشكلي (Formal Examination) — 3-6 أشهر
④ النشر في الجريدة الرسمية (18 شهراً من تاريخ الإيداع أو الأولوية)
⑤ الفحص الموضوعي (Substantive Examination) — بناءً على طلب خلال 3 سنوات
⑥ الرد على الاعتراضات (Office Actions) إذا وُجدت
⑦ المنح ودفع رسوم المنح والنشر
⑧ التجديد السنوي للحفاظ على البراءة
```

## 8. جودة المخرجات — مستوى الإيداع الرسمي | Output Quality Standard

### 8.1 قائمة مراجعة الجودة (Pre-Filing Checklist)

```
المطالبات:
  □ المطالبة 1 مستقلة ولا تُشير لمطالبة أخرى
  □ كل عنصر في المطالبة موصوف في الوصف التفصيلي
  □ لا تناقض بين المطالبات والوصف
  □ الانتقال (comprising/consisting) مناسب ومتسق
  □ كل مطالبة تابعة تُشير بوضوح لمطالبتها الأم
  □ المطالبات المستقلة المتعددة تغطي: جهاز + طريقة + نظام

الوصف:
  □ المجال التقني يُحدد فئة IPC المناسبة
  □ الخلفية تذكر المشكلة بدون تقليل غير ضروري من الفن السابق
  □ كل رقم مرجعي في الرسوم له وصف في الوصف التفصيلي
  □ Best Mode موصوف
  □ البديل والتنويعات تشمل كل ما يمكن أن يُطالب به

الرسوم:
  □ كل شكل مذكور في وصف الرسوم
  □ أرقام مرجعية متسقة عبر جميع الأشكال
  □ لا تناقض بصري مع الوصف

الشكل:
  □ صفحة بيانات المخترع مكتملة
  □ التوقيع والتاريخ (حسب متطلبات الجهة)
  □ تفويض التمثيل إذا كان هناك وكيل براءات
```

### 8.2 معايير اللغة الرسمية

```
عربياً:
  • أسلوب رسمي فصيح — لا عامية، لا اختصارات غير رسمية
  • الجمل القانونية طويلة ودقيقة (هذا مطلوب، ليس خطأً)
  • التعريف قبل الاستخدام: "وحدة المعالجة (10)" ثم "الوحدة (10)"
  • الأرقام المرجعية بين قوسين دائماً

إنجليزياً (للإيداع الدولي/الثنائي):
  • لغة براءات قياسية — لا تقاريرية (لا "the invention works by...")
  • الحاضر التقني: "comprises", "is configured to", "receives"
  • تجنب: "novel", "unique", "breakthrough" في الوصف
```

## 9. التسليمات النهائية | Final Deliverables

عند إنجاز طلب كتابة براءة كامل، قدّم:

```
الحزمة الكاملة (Complete Patent Package):
  📄 ملف براءة الاختراع الكامل (DOCX أو PDF)
      - جميع أقسام الوثيقة
      - مطالبات منسّقة ومرقّمة
  🖼️ الرسوم التقنية (SVG/PDF)
      - كل شكل في ملف منفصل
      - قائمة مراجع الأرقام
  📋 ورقة بيانات المخترع (Inventor Data Sheet)
  📝 ملخص للإيداع (Filing Summary)
      - أبرز المطالبات
      - التصنيف IPC المقترح
      - تقييم أولي للجدة
  ✅ قائمة متطلبات الإيداع المكتملة
```

## 11. تذكيرات نهائية | Final Reminders

> "المطالبة المكتوبة بإتقان تساوي ملايين — كلمة واحدة خاطئة تُفرغها من معناها."

```
⚠️ هذه الوثيقة لأغراض الإعداد والصياغة الأولية.
   يُوصى بمراجعة وكيل براءات اختراع معتمد (Patent Attorney/Agent) قبل الإيداع الرسمي.
   براءات SAIP تقتضي توقيع محامٍ أو وكيل معتمد في بعض الحالات.

✓ عند الشك في نطاق مطالبة → اختر الأوسع مع الحفاظ على الجدة
✓ عند الشك في تضمين تفصيل → أضفه في الوصف لا في المطالبات
✓ الوصف لا يُقلّص لاحقاً (No New Matter Rule) — أضف كل ما تعرفه
✓ اقترح دائماً مراجعة بحث الفن السابق (patent-search) قبل الإيداع
```
